# SPT Forest Fine-Tuning — Session Memory

## Goal
Fine-tune Superpoint Transformer (SPT) for 16-class semantic segmentation of 14 TLS/MLS forest
plots. Dataset: https://zenodo.org/records/17396681 (SegmentedForests, Forestry 2025).

---

## Hardware
- GPU: RTX 4080, 16 GB VRAM
- RAM: 32 GB, 20 CPU cores
- OS: Ubuntu 24.04 LTS
- CUDA driver: 12.8 (runs cu121 PyTorch without issues)

## Dataset Facts

### File layout
- **Original files** (do not delete): `data/plot_01.laz … data/plot_14.laz`
- **Pre-split output** (generated by `scripts/prepare_forest_data.py`):
  ```
  data/forest/raw/
    train/  plot_01.laz … plot_14.laz   (Split == 0, ~2.3 GB total)
    val/    plot_01.laz … plot_14.laz   (Split == 1, ~1.3 GB total)
    test/   plot_01.laz … plot_14.laz   (Split == 2, ~1.2 GB total)
  ```

### Point attributes
| Attribute | Available | Notes |
|-----------|-----------|-------|
| XYZ | ✓ | Real-world metres, plots ~28–43 m diameter |
| RGB | ✓ | uint16 0–65535 → normalised to float32 [0, 1] |
| Class | ✓ | Extra-byte int8; raw IDs 0–13, 22, 23 |
| Split | ✓ | Extra-byte int8; 0=train, 1=val, 2=test per point |
| Intensity | ✗ | All zeros — excluded |
| Return number | ✗ | All zeros — excluded |

### Class remapping (raw → train ID)
Raw IDs 0–13 stay as-is. Raw **22 → 14** (lower_canopy_stems), **23 → 15** (lower_canopy_branches). Anything else → **16 (void)**.

## Key Design Decisions

### 1. Pre-split LAZ files (not `val_mixed_in_train`)
SPT's `val_mixed_in_train` only handles a binary `is_val` flag. Our Split field has 3 values.
Pre-splitting to separate subdirectories avoids framework hacks and is the cleanest approach.

### 2. Unique cloud IDs per stage
- train: `plot_01` … `plot_14`
- val:   `plot_01_val` … `plot_14_val`
- test:  `plot_01_test` … `plot_14_test`

`id_to_relative_raw_path` strips the `_val`/`_test` suffix and maps to the correct subdirectory.
No `val_mixed_in_train` or `test_mixed_in_val` flags needed.

### 3. Tiling: `pc_tiling=2` (4 sub-tiles per plot)
plot_08 is 280 M pts — needs splitting for 16 GB VRAM. PC tiling splits along the principal
XY axis giving geometrically coherent tiles. If OOM occurs on plot_08, increase to `pc_tiling=3`.

### 4. Features: RGB + geometric (no intensity)
```
partition_hf: [rgb, linearity, planarity, scattering, verticality, elevation]
point_hf:     [linearity, planarity, scattering, verticality, elevation, rgb]
```

### 5. Key preprocessing params
| Param | Value | Rationale |
|-------|-------|-----------|
| voxel | 0.05 m | Dense TLS; between S3DIS (0.03) and DALES (0.1) |
| knn | 25 | Sufficient at 5 cm voxel for outdoor plots |
| knn_r | 3.0 m | Outdoor search radius |
| pcp_regularization | [0.05, 0.2, 0.5] | 3 hierarchy levels |
| graph_gap | [0.5, 2.0, 8.0] m | Outdoor scale (S3DIS uses [0.2, 0.5, 1]) |
| sample_graph_r | 7 m | Subgraph radius |
| sample_graph_cylindrical | True | Outdoor scenes |

  ckpt_path=logs/<run>/checkpoints/best.ckpt

## Known Pitfalls
- **plot_08 OOM risk**: 280 M pts even after splitting. If CUDA OOM during preprocessing,
  increase `pc_tiling: 3` in `configs/datamodule/semantic/forest.yaml`.
- **graph_chunk**: default `[1e6, 1e5, 1e5]` — reduce if OOM during graph construction step.
- **Classes 14 & 15** (raw 22/23) appear only in plot_10 with very low frequency (~3%).
  Expect low per-class IoU for these classes.
- **`lazrs` backend**: laspy needs `pip install laspy[lazrs]` for LAZ file support.
